APP_FORGE Hammer

A preview of what's coming in the next generation of APP_FORGE. The current public release remains v2.1 — this page tracks progress toward v2.3, nothing more.

This is not a release. Nothing here is downloadable yet. Features listed below are being actively built and may change before Hammer ships. Check the main page for the current, stable v2.1 release.

What's landing in Hammer

Configurable Resource Folders
Apps can declare a shared "_GLOBAL" resource folder — license files, transforms, shared config — independent of version. Opt-in per app, works the same way for every current and future application.
Native AOT Engine
The core engine compiles to a single native executable — no .NET runtime install required on target systems, faster startup, smaller footprint.
Live Log Streaming
Runs triggered without an interactive session (e.g. via baramundi Deploy Script) now write their log in real time — tail it like any other live log, no more waiting until completion to see progress.
Automatic Bundle Management
One permanent job per application, pointing at a bundle that always carries the current version — versioned test jobs are cleaned up automatically as new releases roll in.
Expanded Version Sources
Beyond GitHub Releases and direct downloads: vendor JSON APIs, HTTP redirect-based version detection, and HTML page scraping for vendors that expose no clean API.
PSADT / BDS Integration
Deep integration with PowerShell App Deployment Toolkit-based installs, including automatic detection-rule handling and production promotion once testing passes.

For build systems & internal tooling

This preview also publishes a machine-readable manifest for internal tooling to check against — not a public update API, just a stable place to look.
